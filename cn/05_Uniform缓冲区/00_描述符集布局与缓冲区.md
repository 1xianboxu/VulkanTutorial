## 描述符集布局

描述符集布局指定着色器中使用的资源绑定：

```c++
VkDescriptorSetLayout descriptorSetLayout;

void createDescriptorSetLayout() {
    VkDescriptorSetLayoutBinding uboLayoutBinding{};
    uboLayoutBinding.binding = 0;                                    // 对应着色器 binding = 0
    uboLayoutBinding.descriptorType = VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER;
    uboLayoutBinding.descriptorCount = 1;
    uboLayoutBinding.stageFlags = VK_SHADER_STAGE_VERTEX_BIT;       // 仅顶点着色器使用
    uboLayoutBinding.pImmutableSamplers = nullptr;

    VkDescriptorSetLayoutCreateInfo layoutInfo{};
    layoutInfo.sType = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_LAYOUT_CREATE_INFO;
    layoutInfo.bindingCount = 1;
    layoutInfo.pBindings = &uboLayoutBinding;

    if (vkCreateDescriptorSetLayout(device, &layoutInfo, nullptr, &descriptorSetLayout) != VK_SUCCESS) {
        throw std::runtime_error("failed to create descriptor set layout!");
    }
}
```

### 在管线布局中引用

```c++
VkPipelineLayoutCreateInfo pipelineLayoutInfo{};
pipelineLayoutInfo.sType = VK_STRUCTURE_TYPE_PIPELINE_LAYOUT_CREATE_INFO;
pipelineLayoutInfo.setLayoutCount = 1;
pipelineLayoutInfo.pSetLayouts = &descriptorSetLayout;  // 引用描述符集布局
```

## Uniform 缓冲区对象

### 着色器端

```glsl
#version 450

layout(binding = 0) uniform UniformBufferObject {
    mat4 model;      // 模型矩阵
    mat4 view;       // 视图矩阵
    mat4 proj;       // 投影矩阵
} ubo;

void main() {
    gl_Position = ubo.proj * ubo.view * ubo.model * vec4(inPosition, 0.0, 1.0);
    fragColor = inColor;
}
```

### C++ 端数据结构

```c++
#include <glm/glm.hpp>
#include <glm/gtc/matrix_transform.hpp>
#include <chrono>

struct UniformBufferObject {
    glm::mat4 model;
    glm::mat4 view;
    glm::mat4 proj;
};
```

> ⚠️ **内存对齐**：Vulkan 要求 UBO 成员遵循特定对齐规则。`mat4` 必须按 16 字节对齐。使用 `alignas(16)` 确保安全：
> ```c++
> struct UniformBufferObject {
>     alignas(16) glm::mat4 model;
>     alignas(16) glm::mat4 view;
>     alignas(16) glm::mat4 proj;
> };
> ```

### 🔴 std140 对齐——Vulkan 最隐蔽的陷阱

**这是初学者最常踩的坑**：C++ 结构体的内存布局与 GLSL `std140` 布局不一致导致数据错乱。

#### 陷阱 1：`vec3` 占 16 字节，不是 12 字节

```c++
// ❌ 致命错误！
struct UBO_Wrong {
    glm::mat4 model;      // offset  0, 大小 64
    glm::vec3 lightPos;   // offset 64, 大小 12，但 std140 对齐到 16！
    float intensity;      // C++ 中 offset 76，但 GPU 认为 offset 80！
};
// → lightPos 后面有 4 字节 padding，intensity 的值在 GPU 端是错的！

// ✅ 修复方案 1：使用 alignas
struct UBO_Fix1 {
    alignas(16) glm::mat4 model;
    alignas(16) glm::vec3 lightPos;  // 强制 16 字节对齐
    float intensity;                  // 现在 offset = 80，与 GPU 一致
};

// ✅ 修复方案 2：用 vec4 替代 vec3（最安全）
struct UBO_Fix2 {
    glm::mat4 model;
    glm::vec4 lightPosAndIntensity;  // xyz = pos, w = intensity
};
```

#### 陷阱 2：`bool` 在 GLSL 中是 4 字节

```c++
// ❌ C++ 的 bool 是 1 字节，GLSL 的 bool 是 4 字节
struct UBO_Wrong {
    bool enabled;      // C++ 1 字节，GPU 期望 4 字节 → 后续全错位
    glm::mat4 mvp;
};

// ✅ 使用 VkBool32 或 int32_t
struct UBO_Correct {
    VkBool32 enabled;  // 4 字节，与 GPU 一致
    alignas(16) glm::mat4 mvp;
};
```

#### 陷阱 3：数组元素对齐

```c++
// ❌ GLSL 中 float 数组每个元素按 16 字节对齐（不是 4 字节！）
// layout(std140) uniform { float values[4]; }
// GPU 中 values[0] 在 offset 0，values[1] 在 offset 16！

struct UBO_Wrong {
    float values[4];  // C++ 连续 4*4=16 字节
    // GPU 期望 4*16=64 字节！
};

// ✅ 使用 vec4 数组或手动添加 padding
struct UBO_Correct {
    alignas(16) float value0;
    alignas(16) float value1;
    alignas(16) float value2;
    alignas(16) float value3;
};
```

**std140 完整对齐规则表**：

| GLSL 类型 | 对齐要求 | 大小 | C++ 建议 |
|-----------|---------|------|---------|
| `float` | 4 | 4 | `float` |
| `vec2` | 8 | 8 | `glm::vec2` |
| `vec3` | **16** | 12+4pad | `alignas(16) glm::vec3` |
| `vec4` | 16 | 16 | `glm::vec4` |
| `mat4` | 16 | 64 | `alignas(16) glm::mat4` |
| `bool` | 4 | 4 | `VkBool32` / `int32_t` |
| `int` | 4 | 4 | `int32_t` |
| `float[]` | **16 每元素** | 16×N | 逐元素 `alignas(16)` |

> 💡 **调试方法**：如果渲染结果"扭曲"或矩阵看起来错误，90% 的原因是 UBO 对齐问题。使用 RenderDoc 检查 UBO 的实际内存内容。

### 创建 Uniform 缓冲区（每帧一个）

```c++
std::vector<VkBuffer> uniformBuffers;
std::vector<VkDeviceMemory> uniformBuffersMemory;
std::vector<void*> uniformBuffersMapped;  // 持久映射

void createUniformBuffers() {
    VkDeviceSize bufferSize = sizeof(UniformBufferObject);

    uniformBuffers.resize(MAX_FRAMES_IN_FLIGHT);
    uniformBuffersMemory.resize(MAX_FRAMES_IN_FLIGHT);
    uniformBuffersMapped.resize(MAX_FRAMES_IN_FLIGHT);

    for (size_t i = 0; i < MAX_FRAMES_IN_FLIGHT; i++) {
        createBuffer(bufferSize, VK_BUFFER_USAGE_UNIFORM_BUFFER_BIT,
            VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT | VK_MEMORY_PROPERTY_HOST_COHERENT_BIT,
            uniformBuffers[i], uniformBuffersMemory[i]);

        // 持久映射（Persistent Mapping）——映射后不解除，每帧直接 memcpy
        vkMapMemory(device, uniformBuffersMemory[i], 0, bufferSize, 0, &uniformBuffersMapped[i]);
    }
}
```

> 💡 **持久映射**避免了每帧 map/unmap 的开销。

### 更新 Uniform 数据

```c++
void updateUniformBuffer(uint32_t currentImage) {
    static auto startTime = std::chrono::high_resolution_clock::now();
    auto currentTime = std::chrono::high_resolution_clock::now();
    float time = std::chrono::duration<float>(currentTime - startTime).count();

    UniformBufferObject ubo{};
    ubo.model = glm::rotate(glm::mat4(1.0f), time * glm::radians(90.0f), glm::vec3(0.0f, 0.0f, 1.0f));
    ubo.view = glm::lookAt(glm::vec3(2.0f, 2.0f, 2.0f), glm::vec3(0.0f), glm::vec3(0.0f, 0.0f, 1.0f));
    ubo.proj = glm::perspective(glm::radians(45.0f),
        swapChainExtent.width / (float)swapChainExtent.height, 0.1f, 10.0f);
    ubo.proj[1][1] *= -1;  // ⚠️ Vulkan Y 轴翻转！GLM 默认为 OpenGL

    memcpy(uniformBuffersMapped[currentImage], &ubo, sizeof(ubo));
}
```

> ⚠️ **Vulkan 的 Y 轴方向与 OpenGL 相反**。必须翻转投影矩阵的 Y 分量，否则图像会倒置。

## 知识点总结

| 概念 | 说明 |
|------|------|
| 描述符集布局 | 声明着色器使用的资源类型和绑定点 |
| Uniform 缓冲区 | 每帧更新的着色器常量数据 |
| 持久映射 | 只映射一次，每帧直接 memcpy |
| 内存对齐 | `alignas(16)` 确保 Vulkan 对齐要求 |
| Y 轴翻转 | `proj[1][1] *= -1` |
