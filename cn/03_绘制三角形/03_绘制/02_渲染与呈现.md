## 同步机制

Vulkan 的 GPU 操作是**异步的**——函数返回时操作可能尚未完成。我们需要**显式同步**。

### 信号量 vs 栅栏

```mermaid
graph TD
    subgraph "信号量 Semaphore"
        S1[GPU 操作 A] -->|发信号| S[信号量]
        S -->|等待| S2[GPU 操作 B]
    end
    
    subgraph "栅栏 Fence"
        F1[GPU 操作] -->|发信号| F[栅栏]
        F -->|等待| F2[CPU 代码]
    end
    
    style S fill:#fff9c4
    style F fill:#ffccbc
```

| 同步原语 | 用途 | 等待方 |
|----------|------|--------|
| **信号量**（Semaphore） | GPU-GPU 同步 | GPU 等待 |
| **栅栏**（Fence） | GPU-CPU 同步 | CPU 等待（阻塞主机） |

> 📌 **选择原则**：
> - 交换链操作（GPU 内部）→ **信号量**
> - 等待上一帧完成（CPU 需要等 GPU）→ **栅栏**

## 创建同步对象

```c++
VkSemaphore imageAvailableSemaphore;   // 图像已从交换链获取
VkSemaphore renderFinishedSemaphore;   // 渲染已完成，可以呈现
VkFence inFlightFence;                 // 上一帧已完成

void createSyncObjects() {
    VkSemaphoreCreateInfo semaphoreInfo{};
    semaphoreInfo.sType = VK_STRUCTURE_TYPE_SEMAPHORE_CREATE_INFO;

    VkFenceCreateInfo fenceInfo{};
    fenceInfo.sType = VK_STRUCTURE_TYPE_FENCE_CREATE_INFO;
    fenceInfo.flags = VK_FENCE_CREATE_SIGNALED_BIT;  // ⚠️ 初始为已发信号状态！

    if (vkCreateSemaphore(device, &semaphoreInfo, nullptr, &imageAvailableSemaphore) != VK_SUCCESS ||
        vkCreateSemaphore(device, &semaphoreInfo, nullptr, &renderFinishedSemaphore) != VK_SUCCESS ||
        vkCreateFence(device, &fenceInfo, nullptr, &inFlightFence) != VK_SUCCESS) {
        throw std::runtime_error("failed to create synchronization objects!");
    }
}
```

> ⚠️ **栅栏必须以 `SIGNALED` 状态创建**！否则第一帧调用 `vkWaitForFences` 会**永久阻塞**——因为没有"上一帧"来发信号。

## drawFrame 实现

```c++
void drawFrame() {
    // 1. 等待上一帧完成
    vkWaitForFences(device, 1, &inFlightFence, VK_TRUE, UINT64_MAX);
    vkResetFences(device, 1, &inFlightFence);  // 手动重置栅栏

    // 2. 从交换链获取图像
    uint32_t imageIndex;
    vkAcquireNextImageKHR(device, swapChain, UINT64_MAX, 
                          imageAvailableSemaphore, VK_NULL_HANDLE, &imageIndex);

    // 3. 重置并记录命令缓冲区
    vkResetCommandBuffer(commandBuffer, 0);
    recordCommandBuffer(commandBuffer, imageIndex);

    // 4. 提交命令缓冲区
    VkSubmitInfo submitInfo{};
    submitInfo.sType = VK_STRUCTURE_TYPE_SUBMIT_INFO;

    VkSemaphore waitSemaphores[] = {imageAvailableSemaphore};
    VkPipelineStageFlags waitStages[] = {VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT};
    submitInfo.waitSemaphoreCount = 1;
    submitInfo.pWaitSemaphores = waitSemaphores;      // 等待图像可用
    submitInfo.pWaitDstStageMask = waitStages;         // 在颜色输出阶段等待

    submitInfo.commandBufferCount = 1;
    submitInfo.pCommandBuffers = &commandBuffer;

    VkSemaphore signalSemaphores[] = {renderFinishedSemaphore};
    submitInfo.signalSemaphoreCount = 1;
    submitInfo.pSignalSemaphores = signalSemaphores;   // 完成后发信号

    if (vkQueueSubmit(graphicsQueue, 1, &submitInfo, inFlightFence) != VK_SUCCESS) {
        throw std::runtime_error("failed to submit draw command buffer!");
    }

    // 5. 呈现
    VkPresentInfoKHR presentInfo{};
    presentInfo.sType = VK_STRUCTURE_TYPE_PRESENT_INFO_KHR;
    presentInfo.waitSemaphoreCount = 1;
    presentInfo.pWaitSemaphores = signalSemaphores;    // 等待渲染完成

    VkSwapchainKHR swapChains[] = {swapChain};
    presentInfo.swapchainCount = 1;
    presentInfo.pSwapchains = swapChains;
    presentInfo.pImageIndices = &imageIndex;

    vkQueuePresentKHR(presentQueue, &presentInfo);
}
```

### 同步流程图

```mermaid
sequenceDiagram
    participant CPU as CPU
    participant GPU as GPU
    participant SC as 交换链
    
    CPU->>CPU: vkWaitForFences（等待 GPU）
    CPU->>SC: vkAcquireNextImageKHR
    SC-->>CPU: imageIndex + 发信号 imageAvailableSemaphore
    CPU->>CPU: 记录命令缓冲区
    CPU->>GPU: vkQueueSubmit（等待 imageAvailable，完成发信号 renderFinished + fence）
    GPU->>GPU: 执行绘制命令
    GPU-->>CPU: 发信号 inFlightFence
    CPU->>SC: vkQueuePresentKHR（等待 renderFinished）
    SC->>SC: 呈现到屏幕
```

> 📌 **`waitStages` 的含义**：GPU 可以在图像可用之前就开始执行顶点着色器等早期阶段，只在需要写入颜色附件时才等待。

## 子通道依赖

渲染通道中的图像布局转换需要正确的子通道依赖配置：

```c++
// 在 createRenderPass() 中添加
VkSubpassDependency dependency{};
dependency.srcSubpass = VK_SUBPASS_EXTERNAL;   // 渲染通道之前的隐式子通道
dependency.dstSubpass = 0;                      // 我们的子通道

dependency.srcStageMask = VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT;
dependency.srcAccessMask = 0;

dependency.dstStageMask = VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT;
dependency.dstAccessMask = VK_ACCESS_COLOR_ATTACHMENT_WRITE_BIT;

// 添加到渲染通道创建信息中
renderPassInfo.dependencyCount = 1;
renderPassInfo.pDependencies = &dependency;
```

> ⚠️ 没有这个依赖，布局转换可能在图像还未从交换链获取时就开始了。

## 退出时等待

```c++
void mainLoop() {
    while (!glfwWindowShouldClose(window)) {
        glfwPollEvents();
        drawFrame();
    }
    vkDeviceWaitIdle(device);  // ⚠️ 必须等待所有 GPU 操作完成才能清理资源！
}
```

> ⚠️ **不加 `vkDeviceWaitIdle`**，退出时验证层会报错——因为正在销毁还在使用的同步对象。

### 🔴 渲染与同步常见错误

#### 错误 1：栅栏未以 `SIGNALED` 创建 → 第一帧死锁

```c++
// ❌ 默认 flags = 0 → 栅栏初始为 unsignaled
VkFenceCreateInfo fenceInfo{};
fenceInfo.sType = VK_STRUCTURE_TYPE_FENCE_CREATE_INFO;
// → 第一帧 vkWaitForFences 永远阻塞（无人 signal 过它）

// ✅ 加上 SIGNALED 标志
fenceInfo.flags = VK_FENCE_CREATE_SIGNALED_BIT;
```

#### 错误 2：`pWaitDstStageMask` 为 nullptr → 崩溃或未定义行为

```c++
// ❌ 设了 waitSemaphores 但没有设 waitStages
submitInfo.waitSemaphoreCount = 1;
submitInfo.pWaitSemaphores = waitSemaphores;
submitInfo.pWaitDstStageMask = nullptr;  // ← 必须提供！

// ✅ waitSemaphores 和 pWaitDstStageMask 是一一对应的数组
VkPipelineStageFlags waitStages[] = {VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT};
submitInfo.pWaitDstStageMask = waitStages;
```

#### 错误 3：`waitStage` 选错 → 不必要的 GPU 阻塞

```c++
// ❌ 在管线最开始就等待 → GPU 完全空闲直到图像可用
VkPipelineStageFlags waitStages[] = {VK_PIPELINE_STAGE_TOP_OF_PIPE_BIT};
// 浪费！顶点处理阶段不需要等待图像

// ✅ 只在颜色输出阶段等待（图像获取完成后 GPU 才写入帧缓冲）
VkPipelineStageFlags waitStages[] = {VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT};
// GPU 可以在等待期间执行顶点/片段着色器的早期阶段
```

#### 错误 4：信号量/栅栏搞反

```c++
// ❌ 用栅栏做 GPU-GPU 同步
vkQueueSubmit(queue, 1, &submit, renderFinishedFence);
// → 栅栏只能 CPU 等待，不能在 vkQueuePresentKHR 中等待

// ❌ 用信号量做 GPU-CPU 同步  
// → 信号量不能在 vkWaitForFences 中等待

// ✅ 记住规则：
// 信号量 = GPU ↔ GPU（交换链获取 → 渲染 → 呈现）
// 栅栏   = GPU → CPU（帧完成 → CPU 可以重用该帧资源）
```

#### 错误 5：退出时不等待 → 验证层报错

```c++
// ❌ 主循环结束后直接清理
mainLoop();
cleanup();  // 此时 GPU 可能还在渲染最后一帧！
// → 验证层报错：destroying object in use

// ✅ 必须等待 GPU 空闲
mainLoop();
vkDeviceWaitIdle(device);
cleanup();
```
